# Contributing / Katkida Bulunma

## Turkce

Turkuaz Labs projelerine katkilar memnuniyetle karsilanir.

Katki gondermeden once:

- Mevcut issue ve pull requestleri kontrol edin.
- Buyuk degisikliklerde once bir issue acarak yaklasimi tartisin.
- Degisikligi tek bir amaca odakli tutun.
- Gereksiz formatlama veya ilgisiz refactor eklemeyin.
- Mumkun olan projelerde testleri calistirin.
- Yeni davranis veya ozellik ekliyorsaniz dokumantasyonu guncelleyin.

### Branch ve Commit

Anlasilir branch adlari kullanin. Ornekler: `fix/...`, `feat/...`, `docs/...`, `chore/...`.

Commit mesajlari kisa ve acik olmali. Tercih edilen bicim:

`feat: ...`, `fix: ...`, `docs: ...`, `refactor: ...`, `test: ...`, `chore: ...`

### Pull Request

Pull request aciklamasinda degisikligin ne yaptigini, neden gerekli oldugunu ve nasil test edildigini belirtin.

## English

Contributions to Turkuaz Labs projects are welcome.

Before submitting a contribution:

- Check existing issues and pull requests.
- For significant changes, open an issue first to discuss the approach.
- Keep each change focused on a single purpose.
- Avoid unrelated formatting or refactoring.
- Run available tests when possible.
- Update documentation when adding or changing behavior.

### Branches and Commits

Use clear branch names such as `fix/...`, `feat/...`, `docs/...`, or `chore/...`.

Prefer concise commit messages using prefixes such as `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, and `chore:`.

### Pull Requests

Describe what changed, why the change is needed, and how it was tested.
